## 12:10 UTC — oracle_ask_sqlite should not write pipeline:shutdown when corpus is fully oracled

**Context**: Mr. Hinds wants `full_cycle_ite` to complete its lora→diary→eval tail even when `storiesMissingKag` returns 0. Currently `oracle_ask_sqlite.coffee` (in @jahbini/pipeline) writes `S.saveThis 'pipeline:shutdown', {...}` in the `if pending.length is 0` branch, which the runner picks up at every subsequent step's `start()` and bails. So once the corpus is fully oracled, no further cycle of the full pipeline can run.

A previous fork of this file in writediary's `scripts/kag_oracle_ite/` to suppress the shutdown line resulted in the relative `require '../_helpers/cache_embedding.coffee'` failing (helper lives in EXEC/scripts/_helpers, not BASE/scripts/_helpers; node has no portable way to find it from BASE since the package has no `exports` field). That fork left the step in a hung `running` state on the mac-mini. The fork has been deleted (writediary `26a73cf`).

**Recommendation**: in upstream `scripts/kag_oracle_ite/oracle_ask_sqlite.coffee`, remove the `pipeline:shutdown` write in the empty-pending branch. The four artifact `make`s stay; only the side-effect line goes. The current branch:

```coffee
if pending.length is 0
  S.saveThis 'pipeline:shutdown',
    by: S.stepName
    reason: 'all stories have already been passed to the sqlite oracle'
    timestamp: new Date().toISOString()
  S.make 'new_story_ids', newStoryIds
  S.make 'oracle_remaining_count', 0
  S.make 'kag_rejects', rejectRows
  S.done()
  return
```

becomes:

```coffee
if pending.length is 0
  console.log "[oracle_ask_sqlite] no pending stories; downstream steps continue"
  S.make 'new_story_ids', newStoryIds
  S.make 'oracle_remaining_count', 0
  S.make 'kag_rejects', rejectRows
  S.make 'kag_viewed', []
  S.done()
  return
```

Two changes from current: (1) the `pipeline:shutdown` write is gone; (2) `kag_viewed` gets an explicit empty-array `make` so downstream wiring doesn't block (currently `S.make 'kag_viewed', pending` happens unconditionally above this branch — verify that's the case in the post-tools/ refactor and drop the redundant make if so).

**Why**: oracle_ask_sqlite is the seam between "populate the KAG once" and "use the KAG repeatedly." The shutdown was reasonable when oracle_ite was the only recipe using it; for full_cycle_ite (oracle + lora + diary + eval in one DAG), it's actively harmful — the pipeline can never complete a cycle on a fully-oracled corpus. The corpus DB isn't going away; making completion the trigger for cycle-end conflates two concerns.

**How to verify**: launch `full_cycle_ite` on a corpus where all 169 stories already have kag_entries. With current upstream, the pipeline shuts down at oracle_ask_sqlite and `out/eval/eval_score.json` is stale (last cycle's). With the fix, the run proceeds through `select_lora_stories_ite → run_lora_train_ite → ... → judge_run_ite` and writes a fresh `eval_score.json` with a new `judged_at` timestamp.

**Related**: the writediary repo currently carries `scripts/story/reset_base_environment_ite.coffee` with a cycle cap + adapter-aligned `loraCycleReset` (commit `96100c8`). That guarantees fresh story rotation when the adapter file is wiped, and shuts the pipeline down after 10 completed `loraTrainingRuns`. Independent of the oracle change.

# spystory recipe

Sibling of `story`, pinned to the `spy` dramatic grammar
(`dramatic_grammars.yaml`). Selectable from the UI recipe dropdown.

## Shape (2026-08-04, post-cleanup)

- **One generator.** `generate_diary_with_adapter_ite` runs by
  default (`depends_on: [build_diary_prompt_ite]`); no
  `generate_diary_without_adapter_ite` step exists in the recipe.
  No `[never]` gates and no override flips.
- **`state_extractor` and `archive_chapter`** depend on the adapter
  step directly (`needs: [diary_adapted_text, ...]`).
- **Artifact registry** carries only `diary_adapted_*` — the
  `diary_base_*` targets were removed with the step.
- **Grammar pin:** `story_beats.grammar: spy` and
  `collect_diary_kag_ite.grammar: spy` are set in the recipe.

## Override (`pipes/story/override/spystory.yaml`)

The override is minimal: pipeline selector + Phase 1 LEPA wiring
(cast_supplement artifact registration, cast_genesis step,
story_spine's cast_genesis dep). No generator flips.

## Why one-generator

Earlier the recipe shipped both generators with the adapter one
gated `depends_on: [never]` and the override flipping it on. That
pattern violated the "never means never" convention (see the
feedback memory), and it produced a real toposort crash when the
override for a given pipeline gated the wrong generator.
`spystory` collapses to the single adapter path so there is no gate
to flip.

If a spy-trained adapter is ever produced and a base-comparison
generator is wanted back, add a second step block with its own
`makes: [...]` and wire a second consumer to it (do NOT introduce a
`[never]` sibling that a downstream `depends_on` points at).

## Blandness notes (from 2026-08-04 autopsy)

Independent of this cleanup, the earlier `spy_run_autopsy` found the
main drivers of bland output were:

1. **UI emotion dropdowns overrode the grammar** — every kind in
   `diary_kag.json` showed `source=ui_override`, so the spy grammar
   contributed nothing to KAG retrieval that run. The knobs are
   sticky between sessions.
2. **KAG corpus is Jim's writing.** There is no spy corpus, so
   passages always sound like Jim.
3. **Generator system prompt says "You are Jim from St. John's."**
   Register bleed is guaranteed regardless of grammar.
4. **State_extractor parse_error** — chapter_state had
   `status=conflict` with no diagnostic beats; continuity signal
   nonfunctional that run.

Levers left for later: rewrite the diary system prompt for spy;
narrow or clear the UI emotion overrides so the grammar's map
drives; investigate the state_extractor parse failure.

## `default` sentinel semantics (2026-08-05)

The five UI dropdowns
(`scene`/`arrival`/`disturbance`/`reflection`/`realization_emotion`)
have a blank option that the UI's dropdown renderer draws as
`(default)` with an empty `value=""` attribute
(`ui/index.html:704`). Recipe options list is generated by
`ui_server.coffee:310-332` from a `SELECT DISTINCT keyword FROM
kag_entries` — the corpus keywords only, no `default` literal.

`collect_diary_kag_ite`'s override loop now treats **any** UI value
that is empty OR case-insensitively equals the string `default`
(after trimming) as a no-op: the derived grammar emotion stands
with `provenance.source = 'beat[N]'`. Any other non-empty value
still wins as an ui_override (verified by
`test/default_sentinel_probe.coffee`; passes 34/34 across ``, `''`,
`'default'`, `'  Default  '`, and `'anger'`).

**Crash mechanism trace.** I could not reproduce a crash from
static tracing. The `kagByKeyword{default}.jsonl` request routes
through `meta/sqlite.coffee:721-737` which does
`SELECT ... WHERE keyword = 'default'` — with no matching rows the
handler returns `[]`, `selectMatches` yields no matches, and
downstream `flattenEntries` silently produces an empty keyword
list. No throw is visible along that path in the current code. The
sqlite has no `default` keyword either (query on
`pipes/story/runtime.sqlite` returned zero rows).

If the crash was real at the point of use, the sentinel now
prevents the value from ever traveling to that call site — so per
the "fix upstream, no shallow prescreens" rule, the observable
should be gone regardless. If it recurs, the actual stack trace
would tell us where; static reading did not pin it down.

No recipe edits were required. The recipe's UI_dropdown default
value stays `""`, and the UI renders `(default)` for it — the
sentinel handles both `""` and any literal `default` a differently-
rendering client might send.

## Style meter (offline)

`test/style_meter.coffee` — regex-only, read-only. Reports
per-100-word densities (similes, X-of-Y informational metaphors,
dialogue opens, violence/intensity verbs) and a tail-of-letter
aphorism count. Default target set: `out/diary_adapted.txt` plus
every archived chapter's diary text under `out/chapters/*/`.

Run:

    cd pipes/story && npx coffee ../../test/style_meter.coffee

Baseline from the current run (both files are the same 880-word
chapter; the archived and working copy):

    similes 0.57/100w · x_of_y 0.68/100w · dialogue 1.14/100w ·
    violence 0.45/100w · aphorisms_tail 8

Output goes to stdout AND `test/logs/style_meter/<ts>/report.json`.
Extend `VIOLENCE_VERBS` at the top of the script to add tokens.
